# 怎麼寫一張 AI 能做好的 ticket

AI 計畫的品質上限就是 ticket 的品質。使用 `AI 開發任務` 範本（New issue 時選擇）。

## 好 ticket 的特徵

| 項目 | 好 | 壞 |
| --- | --- | --- |
| 目標 | 「訂單超過 3000 元免運費」 | 「優化運費」 |
| 驗收條件 | 每條可被測試：「當金額為 3000 時，運費為 0」 | 「運作正常」 |
| 範圍 | 明確寫「不包含優惠券疊加」 | 沒寫，AI 自己猜 |
| 限制 | 「不可更改既有 API 回應格式」 | 沒寫 |

## 適合與不適合交給 AI 的任務

| 適合 | 先由人主導（可請 AI 輔助） |
| --- | --- |
| 邊界清楚的功能、錯誤修正、補測試、重構、文件 | 資料庫 migration、金流與權限、跨系統的大改動、效能調校、缺乏測試的遺留程式碼 |

## 流程提醒

1. 建立 issue 後**指派負責人**。AI 每個階段完成都會 mention 這個人。
2. 貼 `ai:plan`。若 AI 問問題（標籤 `needs:clarification`），回覆後**再貼一次** `ai:plan`
   （標籤會在每一輪結束時被移除）。
3. 看到「AI Plan」後認真審閱：目標、驗收條件、影響分析、測試計畫、風險。要調整就直接留言。
4. 同意後貼 `plan-approved`（這是關卡 1，代表你為這份計畫負責）。
5. 收到 PR 通知後審查程式碼；要 AI 修改就在 PR 留言 `@claude 請 ……`。
6. 合併是關卡 2。

## 不要做的事

- 不要在 ticket 或留言裡貼密碼、金鑰、客戶資料。
- 不要把 `plan-approved` 貼在沒看過計畫的 issue 上。
- 不要要求 AI 修改 `.github/`、`.claude/`、`CLAUDE.md`：這些由人修改（Agent 在 CI 中也被擋下）。
