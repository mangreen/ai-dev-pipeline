# ADR-0005: API key at organization level for authentication

- Date: 2026-10-21
- Status: Accepted
- Related: [DESIGN.md](../architecture/DESIGN.md) section 11

## Context

`claude-code-action` can authenticate with an API key, a subscription OAuth token, a cloud
provider (Bedrock, Vertex, Foundry) through OIDC, or workload identity federation. The team has
10–20 people and several repositories.

## Options considered

1. `ANTHROPIC_API_KEY` stored as an organization-level Actions secret.
2. `CLAUDE_CODE_OAUTH_TOKEN` generated by one person with `claude setup-token`.
3. Workload identity federation / cloud provider OIDC (no long-lived secret).

## Decision

Option 1 to start, with a dedicated key and a spend limit. Move to option 3 when the security
team requires no long-lived secrets.

## [Trade-off Analysis]

| Option | Pros | Cons |
| --- | --- | --- |
| 1 API key | Works across repos; usage billed and limited centrally; simple | Long-lived secret to rotate |
| 2 OAuth token | Uses an existing subscription | Tied to one person's subscription (the official docs advise against sharing it across a team); personal quota is shared with their own use |
| 3 Federation/OIDC | No stored secret | More setup (Console service account, rules, cloud permissions) |

Reason: simplest option that is correct for a team and keeps cost visible.

## Consequences

- Create a separate API key (and workspace if available) only for the pipeline; set a spend limit.
- Rotate on staff changes; scope the secret to the repositories that need it.
